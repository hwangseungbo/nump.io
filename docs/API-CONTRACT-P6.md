# API-CONTRACT-P6 — 환자 회원가입

P4/P5 계약(docs/API-CONTRACT-P4.md, -P5.md)의 공통 규약을 따른다.

## 1. 설계 원칙

- **환자만 가입 가능.** 의사·간호사·관리자 계정은 병원(admin)이 발급한다 — 가입 경로로
  의료진 권한을 얻을 수 없어야 한다. `/api/signup`은 무조건 `role='patient'`로 생성한다.
- **기존 기록 승계 = `patients.user_id` 연결.** 병원에 내원 이력이 있는 환자(EMR 행은
  있지만 계정이 없는 환자)가 가입하면, 별도 데이터 이관 없이 연결 한 번으로 진료기록·
  처방·수납·예약이 전부 새 계정에 붙는다.
- **매칭 기준: 이름 + 생년월일 + 휴대폰 번호(숫자만 비교).** `user_id IS NULL`인 환자 중
  세 값이 모두 일치하는 환자가 **정확히 1명**일 때만 연결한다. 0명이거나 2명 이상
  (동명이인 등 모호한 경우)이면 신규 환자 행을 만든다.
  - 실서비스라면 휴대폰 본인인증으로 대체할 지점. 데모에서는 입력값 매칭으로 갈음한다.
  - 주민등록번호는 저장하지도, 받지도 않는다.

## 2. POST /api/signup (공개)

요청:
```json
{ "username": "kimcs", "password": "********", "name": "김철수",
  "birth_date": "1981-03-12", "phone": "010-2001-1001", "sex": "M" }
```

검증 (실패 시 400 + `{error}`):
- username: `^[a-z0-9_]{4,20}$` (소문자로 정규화 후 검사)
- password: 8자 이상
- name: 1~30자
- birth_date: `YYYY-MM-DD`, 1900-01-01 이후, 미래 불가
- phone: 숫자만 추출해 `^01\d{8,9}$` → `010-0000-0000` 형태로 정규화 저장
- sex: `M`/`F` 외의 값은 null 처리 (선택 입력)

처리 (단일 트랜잭션):
1. users INSERT (`role='patient'`, profile에 birth_date·phone) — username 중복이면 409
2. 미연결 환자 매칭 → 1명이면 `UPDATE patients SET user_id`, 아니면 patients INSERT
3. 세션 발급 + `bn_session` 쿠키 설정 (로그인과 동일 규격) — 가입 즉시 자동 로그인

응답 200:
```json
{ "ok": true, "role": "patient", "name": "김철수", "linked": true }
```
`linked` = 기존 환자와 연결됐는지. 프론트는 이 값으로 안내 문구를 분기한다.

## 3. 프런트엔드

- `platform/signup.html` — login.html과 동일한 시각 언어. 필드: 아이디 / 비밀번호+확인 /
  이름 / 생년월일(date) / 성별(M·F 토글) / 휴대폰. 성공 시 linked 여부에 따른 안내 후
  1.6초 뒤 `patient/index.html`로 이동. 이미 로그인 상태면 자기 대시보드로 리다이렉트.
- `platform/login.html` — foot에 "환자 회원가입" 링크 추가.
- guardPlatform은 `/platform/(doctor|nurse|patient|admin)/`만 보호하므로 signup.html은
  비로그인 접근 가능 (수정 불필요).

## 4. 부속 A — 메인 페이지 로그인 상태 표시 (index.html)

상단바 우측 `#authBox`: 로그인 시 "{이름}님 · {역할}" + 로그아웃 버튼(POST /api/logout 후
새로고침), 비로그인 시 "로그인" 링크. DOM 노드 생성 방식(innerHTML에 이름 미주입).

## 5. 부속 B — 대시보드 챗 역할별 실데이터 컨텍스트 자동 첨부

공용 챗(ai.js)이 요청 body에 **`ctx: true`** 를 넣어 보내면, `/api/medgemma-chat` 프록시가
세션의 역할에 맞는 실데이터 요약을 message 앞에 첨부한다 (ctx 필드는 업스트림 전달 전 제거):

- **환자**: 이름/성별/만나이, 다가오는 예약(최대 5), 복용 처방(최대 6), 최근 진료 1건,
  미납 진료비(최대 3)
- **의사**: 이름/진료과, 본인 담당 오늘 예약(최대 12, 시각·종류·환자명·상태),
  발급 대기 서류 종류별 건수, 이번 달 진료 건수, 현재 입원 환자 수
- **간호사**: 이름/병동, 현재 입원 환자 수, 오늘 투약·처치·검사 일정(종류·상태별 건수),
  발급 대기 서류 건수, 오늘 작성된 간호기록 건수
- admin·비로그인은 첨부 없음. ctx 미전송 요청(SageFM 환자 요약 등 목적형 프롬프트,
  메인 공개 챗)은 원문 그대로 전달.
- 매 메시지마다 최신 DB 조회 (세션 중 변경도 즉시 반영). 공통 지시: "기록에 없는 내용은
  지어내지 말 것, 안내문 존재를 언급하지 말 것" (CTX_HEAD).
- DB 미가동·파싱 실패 시 원문 그대로 전달 (그레이스풀 폴백).
